# TOOL-002 — Reverse SIMPSONS.EXE in Ghidra

- **Status:** DONE (2026-10-21): analysed, exported, tooled; anchors documented in
  [GHIDRA.md](../GHIDRA.md)
- **Priority:** P2
- **Module:** Tools
- **Files:** `tools/ghidra/` (`analyze.sh`, the Ghidra scripts, `rtti_vtables.py`),
  `docs/GHIDRA.md`

## Context
The original `Simpsons.exe` is the reference for the formats and the logic. A targeted
reverse in Ghidra was to document the critical functions: game loop, P3D and `.con`
parsing, P3DZ, the RMV movies.

## Done
- `Simpsons.exe` and `pddidx8r.dll` imported and analysed headless (Ghidra 12.1.2);
  `tools/ghidra/analyze.sh` redoes it from the game's files.
- Exported: 13171 functions of the executable and 1461 of the renderer, their strings with
  the functions using them, imports, exports, 1339 class names, the decompiled C of every
  function (13091 of the executable, 1 failed), and 1605 virtual function tables rebuilt
  from the RTTI (Ghidra's analyzer labels the type descriptors but not the tables). The
  output is the game's code and stays out of git.
- Found and documented (GHIDRA.md, "What is where"):
  - the executable is the whole game, behind a copy protection (two extra sections, the
    entry point in one, imports resolved at run time);
  - game flow: `GameFlow` and its contexts;
  - P3D loading and P3DZ: `tChunkFile`'s constructor reads the magic (plain, byte-swapped,
    `P3DZ` with its uncompressed size), `tP3DFileHandler` and the per-chunk loaders;
  - scripts: `Console` and `ConsoleFileHandler`, the command name table;
  - movies: Bink under radcore's `radMoviePlayerBink`;
  - rendering: `RenderManager`, the render layers, Pure3D's `tView`, `tPointCamera`, and
    pddi's fog, which settled [LEVEL-FOG](LEVEL-FOG.md).
- P3DZ needed no reverse in the end: it had been solved from the data (P3D-016).
