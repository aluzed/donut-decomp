# TOOL-004 — Make donut-codegen run, enrich p3d.json, regenerate

- **Status:** DONE (2026-10-21)
- **Priority:** P2
- **Module:** Tools
- **Files:** `dev/codegen/generate.sh`, `dev/codegen/hand-edits.patch`,
  `dev/codegen/p3d.json`, `dev/codegen/p3d.unused.json`, `dev/codegen/cmd.json`,
  `dev/codegen/System.Security.Permissions.dll`, `src/P3D/P3D.generated.*`,
  `src/Scripting/Commands.generated.cpp`

## Context
The P3D chunk classes are generated by `donut-codegen.exe` from `p3d.json`
(`src/P3D/P3D.generated.*`), the script commands from `cmd.json`
(`src/Scripting/Commands.generated.cpp`). The generator ran (2026-08-22), but its output
was not what the repository held: glm types where the engine has its own, another
formatting, hand edits, and `p3d.json` describing 25 classes the repository did not have
and missing 2 it did. Regenerating would have broken the build.

## Done
**`dev/codegen/generate.sh` regenerates the three files exactly as committed**
(`--check` compares without writing):

1. `donut-codegen.exe` (built for the .NET Framework) runs on .NET 8 from a copy with a
   runtime configuration. Its command generator needs `System.Security.Permissions`,
   which .NET 8 does not ship: the assembly is in `dev/codegen/`, from its NuGet package
   (8.0.0, `lib/net8.0`, MIT), like the generator's other two.
2. Unix line ends; glm's types and includes become the engine's (`glm::vec3` ->
   `Vector3`, `<glm/vec3.hpp>` -> `"Core/Math/Vector3.h"`...).
3. clang-format 18 with the repository's `.clang-format`.
4. `hand-edits.patch` (13 hunks): what `p3d.json` cannot say. `AnimDynamicPhysics` takes
   its model from two wrapper chunk types; `MultiControllerTracks` reads interleaved
   arrays; `Intersect` reads its `SurfaceTypeList` child into a field; the composite
   drawables' skins and effects strip their names' padding; `PrimitiveGroup` has
   `GetUvChannelCount`; `<cstdint>`; comments.

**`p3d.json` is the repository's classes, all and only them**, in their order: 113 (122 since P3D-004 and P3D-012 added the controllers and `ExportInfo`),
adding `CompositeDrawableSkin` and `CompositeDrawableEffect` and their lists' children,
and `Vector1Channel`'s values as `float` (the generator wrote `sizeof(f32)`, which did
not compile). The 22 other definitions (25 before P3D-012) (`Light*`, `Tree*`, `StaticPropData`, `Locator`,
`Mesh`...) are in `p3d.unused.json`: those chunks are read by hand elsewhere
(`P3D::StateProp`, `P3D::SpatialTree`, the lights), and at least `Locator`'s generated
code was invalid. They are kept for reference, unverified.

Three hand edits turned out to be the generator's code in other words (the skin and
effect lists' loops, `SurfaceTypeList`'s read); the files now hold the generator's form.

## Needs
`dotnet` 8 or later (`DOTNET=<path>`), clang-format 18 (`CLANG_FORMAT=<path>`; the
`clang-format` package on PyPI ships one), `patch`.
