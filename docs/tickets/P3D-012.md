# P3D-012 — ExportInfo chunks

- **Status:** DONE (2026-10-21)
- **Priority:** P3
- **Module:** P3D
- **Depends on:** —
- **Files:** `dev/codegen/p3d.json`, `dev/codegen/p3d.unused.json`, `src/P3D/P3D.generated.{h,cpp}`,
  `src/Game.cpp` (`debugDrawP3D`)

## Context
The exporter's metadata, kept in the files: which tool exported them, when, by whom, with
which settings. Purely informative. The three chunk types were described in
`p3d.unused.json` (see TOOL-004), unchecked, and not generated.

## What the data says
145 files hold an `ExportInfo` (0x7030), all named "Exported From Maya", with 870
`ExportInfoNamedString` (0x7031: "ExporterVersion" 2.0.2.0, "Exported By", "Exported At",
"Maya Version" 4.0.2...) and 1315 `ExportInfoNamedInteger` (0x7032: "Export Animations",
"Export NIS Scenegraph"...) children. The old description was wrong in two ways:
`ExportInfo` has **no version**, only its name, and it holds **both** kinds of entry, not
the strings only.

| Chunk | Layout |
|---|---|
| `ExportInfo` (0x7030) | name; the named strings and integers as children |
| `ExportInfoNamedString` (0x7031) | name, value (both length-prefixed) |
| `ExportInfoNamedInteger` (0x7032) | name, value u32 |

Every one of the 2330 chunks in the game's files reads to its last byte with this layout.

## Done
- The three described in `p3d.json` (out of `p3d.unused.json`) and generated
  (`dev/codegen/generate.sh`; `--check` clean).
- The P3D debug viewer (`Game::debugDrawP3D`) shows an `ExportInfo`'s entries, read
  through the generated classes. Nothing in the game needs them.

## Acceptance criteria
- [x] `ExportInfo`, `ExportInfoNamedString`, `ExportInfoNamedInteger` generated.
- [x] `ExportInfo` gives both the named strings and the named integers.
- [x] A `.p3d` holding an `ExportInfo` parses without an assert: the layout was checked on
      every chunk of the game's files; the viewer reads them through the generated classes.
