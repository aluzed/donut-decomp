# P3D-008 — Spline, LocatorMatrix, SurfaceTypeList

- **Status:** PARTIAL (2026-08-22) — chunks reversés et parsés ; reste le branchement physique de `SurfaceTypeList`
- **Priority:** P1
- **Module:** P3D
- **Depends on:** —
- **Files:** `dev/codegen/p3d.json:838-850` (les 3 **déjà décrits**), `src/P3D/P3DChunk.h:146,151,152` (ChunkType), `src/P3D/P3D.generated.{h,cpp}` (à régénérer), `src/Level.cpp`

## Contexte

`Spline` (0x3000007), `LocatorMatrix` (0x300000C) et `SurfaceTypeList` (0x300000E)
sont **déjà entièrement décrits dans `p3d.json`** :

- `Spline` : `numPoints: u32`, `points: buffer<vec3[numPoints]>` ;
- `LocatorMatrix` : `transform: mat4` ;
- `SurfaceTypeList` : `numSurfaces: u32`, `surfaces: buffer<u32[numSurfaces]>`.

Mais le codegen n'a **pas été relancé** : aucune des trois classes n'existe dans
`P3D.generated.h`. Nécessaires pour les chemins de caméra (splines) et les types de
surface (physique : route / herbe / eau).

## Approche

1. Lancer `dev/codegen/run.bat` pour générer `Spline`, `LocatorMatrix`,
   `SurfaceTypeList` à partir des définitions existantes. Vérifier au préalable que les
   layouts dans `p3d.json` correspondent au reverse (notamment `SurfaceTypeList` :
   confirmer que chaque surface est bien un `u32`).
2. Vérifier les `Load()` générés dans `P3D.generated.cpp`.
3. Brancher dans `Level.cpp` :
   - `SurfaceTypeList` → fournir l'index de type de surface au système physique
     (`src/Physics/`) lors de la résolution de collision sol.
   - `Spline` / `LocatorMatrix` → exposer pour les chemins de caméra (`AnimCamera`,
     `FollowCameraData` déjà géré).

## Réalisation (2026-08-22)

### Deux des trois définitions de `p3d.json` étaient fausses

Le ticket supposait les trois layouts corrects et le codegen simplement pas relancé. Vérifié
sur les assets réels (3319 fichiers `.p3d`, scan récursif de l'arbre de chunks) :

| Chunk | `p3d.json` d'origine | Réalité |
|---|---|---|
| `LocatorMatrix` | `transform: mat4` | ✅ correct (payload de 64 octets sur 1906 occurrences) |
| `Spline` | `numPoints` puis points | ❌ **il manque un `name`** en tête |
| `SurfaceTypeList` | `numSurfaces` puis `u32[]` | ❌ **un `version: u32` en tête, et les surfaces sont des `u8`** |

Généré tel quel, `Spline` lisait le nom comme un compteur et appelait
`resize(1953392924)` — une allocation de 23 Go.

Layouts corrigés, puis revérifiés sur **7892 occurrences** : arithmétique de taille exacte
à **100 %**, aucun échec.

```
Spline             142 occurrences,   142 exactes
LocatorMatrix     1906 occurrences,  1906 exactes
SurfaceTypeList   5844 occurrences,  5844 exactes
valeurs de surface rencontrées : 0,1,2,3,5,6,7 et 128,133,134
```

`p3d.json` est corrigé en conséquence, donc une future régénération produira le bon code.

### Les chunks sont imbriqués, pas à la racine

`Level::LoadP3D` n'examine que les enfants directs de la racine ; ces trois types vivent
plus bas dans le graphe. `Level::collectSplines()` descend désormais l'arbre et indexe les
splines **par leur nom**. À l'exécution sur le niveau 1 : 13 splines, toutes des rails de
caméra (`r1_cam1SplineShape`, `z2_camera05SplineShape`, `z6_cam3SplineShape`…), de 5 à
8 points — cohérent avec le scan hors-ligne.

### Le codegen ne peut pas être relancé tel quel

`dev/codegen/run.bat` fonctionne et génère bien les 3 classes — plus 25 autres absentes du
dépôt (`Light*`, `Tree`, `Mesh`, `InstancedStaticEntity`, `ExportInfo`, `FrontendTextBible`…,
de quoi débloquer le *parsing* de P3D-002, 005, 006, 007, 010, 011, 012). Mais il émet des
types **glm** (`glm::vec3`, `glm::mat4`) alors que le fichier commité utilise `Vector3` /
`Matrix4x4` : le fichier « généré » a été **adapté à la main** après génération. Une
régénération globale casse donc la compilation. Détail consigné dans `TOOL-004`.

Les trois classes ont par conséquent été ajoutées à la main, dans le style du fichier — sans
toucher aux 107 classes existantes (vérifié : leurs accesseurs sont identiques à ce que le
codegen produit).

## Critères d'acceptation

- [x] `class Spline`, `class LocatorMatrix`, `class SurfaceTypeList` existent dans `P3D.generated.h` (ajoutées à la main, cf. la note sur le codegen).
- [x] Les layouts correspondent au reverse — vérifié sur **7892 occurrences** dans 3319 `.p3d` réels, 100 % exact. Deux définitions de `p3d.json` étaient fausses et ont été corrigées.
- [ ] `SurfaceTypeList` est exploitable côté physique — **non fait**. Ces chunks sont imbriqués sous les objets de collision ; les collecter à plat au niveau du `Level` perdrait l'association surface↔collider, qui est précisément ce dont la physique a besoin. À traiter avec `PHYS-008` (frictions par surface).
- [x] `Spline` expose ses points pour les chemins de caméra — `Level::GetSplines()` les indexe par nom ; 13 rails de caméra chargés sur le niveau 1.
